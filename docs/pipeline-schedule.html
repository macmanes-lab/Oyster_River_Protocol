The three concurrency decisions

  1. Assembler split (always on). Trinity phase 1 and the three short-read assemblers (Trans-ABySS, SPAdes55, SPAdes75, each followed immediately by its own DIAMOND search) run in two threads regardless of --max-parallel. Trinity gets TRINITY_LANE_SHARE of the CPU/mem budget; the short-assembler lane gets the rest. Trinity phase 2 only starts once both lanes release the machine, then runs alone at the full budget.
  2. orthofuser_branch alongside merge_branch. Both only need short_fastas, so they're independent until they join at makeorthout. This is the branch pair behind the test37/test36 timing delta you looked at earlier — each branch only took ~5s on the sample dataset, so the concurrency saved seconds there, but ~5h11m on the full SRR1789336 benchmark.
  3. transrate alongside strandeval. Cheap and independent, so they still run as a small concurrent pair even though BUSCO right before them deliberately does not share its CPU budget with anything — it dwarfs both in wall time.
